# 데이터 무결성 및 자체 PostgreSQL 이전 기준

> 문서 상태: **데이터·권한 작업의 규범 문서**  
> 기준일: 2026-09-13  
> 현재 로컬 실행 범위는 EXECUTION_CONTROL을 따른다. 실제 Supabase 제거·실데이터 이전은 별도 승인 게이트다.

## 목적과 상태 구분

이 문서는 특정 상세 스키마를 복제하지 않고, 현재 Supabase 기반 동작과 향후 자체 PostgreSQL 구현이 모두 지켜야 할 결과 조건을 정의한다.

- **확정:** 자체 PostgreSQL 이전은 무결성·권한을 유지하거나 강화해야 한다. 기술 선택·목표 모델·전환/롤백은 [ADR-001](POSTGRES_ARCHITECTURE_DECISION.md)이 단일 기준이다. 로컬 합성 환경 구현 준비 판정은 READY이며 실제 이전 승인이 아니다.
- **현재 구현 확인:** Supabase Auth, RLS, Security Definer RPC, 브라우저/서버 데이터 접근 코드가 존재한다.
- **로컬 검증 확인:** 회원 완료/못함과 선택적 통증·메모를 한 RPC에서 롤백하는 PGlite 테스트가 있다.
- **미충족:** 숙제 본문과 동작 생성은 클라이언트의 연속 insert라 원자적이지 않다.
- **미충족:** 회원 제출 RPC에 안정적인 요청 ID와 중복 제약이 없어 재시도 멱등성이 없다.
- **미검증:** 운영 Supabase 적용 상태, 실제 계정 간 격리, 실제 데이터 품질, 백업·복원.

`구현됨`, `로컬 검증됨`, `실환경 검증됨`, `운영 적용됨`은 서로 대체할 수 없다.

## 데이터 불변조건

### 1. 회원·센터 소유권

- 모든 회원은 정확히 한 강사 소유 범위에 속한다.
- 숙제·숙제 동작·수행 로그·수업 메모는 부모를 통해 같은 강사 소유권을 유지한다.
- 인증된 강사의 모든 읽기·쓰기·갱신·삭제는 서버/DB에서 소유권을 다시 확인한다. 클라이언트 필터만 신뢰하지 않는다.
- 강사 A는 ID를 추측하거나 직접 API를 호출해도 강사 B의 회원과 하위 데이터를 존재 여부까지 알아낼 수 없어야 한다.
- 초기 1계정 센터에서는 계정 공유, 소유권 이전, 조직 관리자를 암묵적으로 지원하지 않는다.

### 2. 원자성

- 숙제 생성과 1~3개 동작 저장은 한 트랜잭션이다. 동작 하나라도 실패하면 숙제도 남지 않는다.
- 회원의 완료/못함, 통증 여부, 메모, 파생 상태·다음 수업 문장 갱신은 제출 1건의 한 트랜잭션이다.
- 토큰 회수와 동시에 진행되는 열기·제출은 행 잠금 또는 동등한 직렬화 규칙으로 일관된 결과를 낸다.
- 데이터 이전 배치는 부모와 자식, 권한 메타데이터가 모두 검증된 경우에만 완료로 표시한다.

### 3. 멱등성

- 네트워크에서 재시도될 수 있는 모든 업무 쓰기는 클라이언트가 재사용하는 안정적인 요청 ID를 받는다. 인증 라이브러리 내부 쓰기는 해당 라이브러리의 세션·일회성 검증 계약으로 검사한다.
- 요청 ID의 유일성 범위는 작업 종류와 대상 집계(예: 숙제 제출)까지 포함해 DB 제약으로 강제한다.
- 동일 요청 ID와 동일 payload 재실행은 같은 성공 결과를 반환하며 새 로그나 상태 전이를 만들지 않는다.
- 동일 요청 ID에 다른 payload가 오면 덮어쓰지 않고 충돌로 거절한다.
- 멱등 결과를 다시 반환할 때도 현재 소유권·세션 또는 토큰 유효성을 먼저 검사한다. 비밀값을 결과 캐시에 넣지 않는다. 구체적인 키 범위·payload 정규화·응답 유실/재발급 계약은 ADR-001 §7을 따른다.
- 동시 요청, 응답 유실 후 재시도, 새로고침, 여러 탭을 테스트한다.
- 목표 제출은 수행 사실과 feedback를 같은 트랜잭션의 한 묶음으로 저장한다. 같은 key는 재시도이고, 새 key·새 performed_at의 정상 후속 수행은 별도 관찰 기록이다. 정정은 원본 삭제 없이 observation 관계·수행 시각을 유지한 새 버전/supersedes_id로 구분한다. 최신 요약은 최신 관찰의 최신 정정 기준이며 과거 수행을 덮어쓰지 않는다. 상세 모델은 ADR-001 §6~7, 실행 계약은 [P0 검사표](P0_VERIFICATION_MATRIX.md)를 따른다.

### 4. 회원 링크 토큰 접근

- 토큰은 예측하기 어려운 충분한 엔트로피와 유일성을 가져야 한다.
- 유효기간이 지나거나 회수된 토큰은 열기와 제출 모두 거절한다.
- 토큰 소지는 해당 숙제의 필요한 표시 정보와 제출 권한만 부여한다. 강사 권한, 회원 목록, 다른 숙제·로그 조회 권한을 부여하지 않는다.
- 응답은 전화번호, 다른 회원 정보, 내부 소유권 필드 등 회원 화면에 불필요한 데이터를 포함하지 않는다.
- 원문 토큰은 애플리케이션·분석·오류 로그에 남기지 않고 URL·리퍼러·지원 캡처 노출을 최소화한다.
- 목표 PostgreSQL은 원문 대신 해시 저장을 사용한다. 발급 엔트로피·해시·만료·회수·재발급과 재시도 시 원문 취급은 ADR-001 §7이 기준이다. 현재 Supabase 원문 컬럼은 이 문서 작업에서 변경하지 않는다.

### 5. 참조·이력·시간

- 부모 없는 숙제 동작·로그·수업 메모가 존재하지 않는다.
- ID, 생성 시각, 수정 시각, 토큰 만료 시각은 이전 전후 의미와 시간대를 유지한다.
- 상태 값은 허용된 전이만 거치며 파생 요약은 원본 로그에서 재생성 가능해야 한다.
- 데모·합성 데이터는 실제 데이터와 물리적 또는 명시적 환경 경계로 분리한다.
- 실제 데이터의 삭제·보관·내보내기 정책은 운영 도입 전에 확정한다.

## 자체 PostgreSQL 이전 방향

1. **현재 계약 고정:** 현재 API/RPC 결과, 상태 전이, 권한 실패 응답, 데이터 규모를 문서와 계약 테스트로 기록한다.
2. **경계 분리:** UI가 Supabase SDK 세부 구현에 직접 의존하지 않도록 인증·데이터 접근 인터페이스를 정의한다.
3. **목표 설계:** 자체 PostgreSQL 호스팅, 연결 계층, 인증 제공자, 비밀 관리, 백업·복원, 관측성, 배포 주체를 결정한다.
4. **동등성 구현:** 소유권, 원자성, 멱등성, 토큰 최소 권한을 DB 제약과 서버 트랜잭션으로 구현한다.
5. **리허설:** 합성 데이터로 전체 이전·검증·롤백을 반복하고 예상 중단 시간과 책임자를 기록한다.
6. **실데이터 전환:** 사용자의 별도 승인과 백업 확인 후 모든 원본 writer를 중지하는 단일 쓰기 전환을 기본으로 한다. 기본 이중 쓰기는 금지한다. 실제 데이터 없음이 확인되면 일반 이관 시스템 없이 빈 새 DB에서 시작한다.

위 1~6은 개념 순서다. 실행 단계는 [EXECUTION_CONTROL.md](EXECUTION_CONTROL.md)를 따른다. 2단계 기술 결정 이후 3단계에서 목표 계약과 기존 구현 실패를 고정했다. 새 DDL·실제 이전은 아직 시작하지 않았다.

## 이전 전에 필요한 검사

| 영역 | 최소 검사 |
| --- | --- |
| 소유권 | 두 강사 계정으로 모든 부모/자식 CRUD 교차 접근 거절, 존재 유출 확인 |
| 원자성 | 숙제 동작 중간 실패, 통증 로그 실패, 파생 상태 갱신 실패를 주입하고 전부 롤백 확인 |
| 멱등성 | 같은 요청 ID 순차·동시 재시도, 다른 payload 충돌, 응답 유실 재시도 |
| 토큰 | 정상·없는·만료·회수 토큰, 다른 숙제 접근, 열기/제출과 회수 경합 |
| 참조 무결성 | orphan, 중복, null/범위/상태 제약, 삭제 규칙 검사 |
| 이전 동등성 | 테이블별 행 수, 주요 집계, ID/FK, 시각, 상태, 표본 checksum 비교 |
| 복구 | 백업 생성, 새 환경 복원, 애플리케이션 읽기/쓰기 smoke test, 롤백 시간 측정 |
| 운영 경계 | 운영 비밀·관리 권한·로그 마스킹·실데이터 접근 승인 확인 |

`npm run verify`와 빌드 성공만으로 위 검사를 통과 처리하지 않는다.

## 로컬 구현과 실제 이전 게이트

로컬 합성 환경의 구현은 ADR-001의 READY 판정으로 준비됐다. 사용자 최신 실행 순서는 3단계 P0 계약 → 4단계 로컬 PostgreSQL/스키마 → 5단계 인증/서버 경계다. 기술 결정의 존재를 새 DB의 보안·복구 검증 완료로 취급하지 않는다.

### 실제 데이터/운영 전환

다음이 모두 충족되기 전에는 실제 이전을 시작하지 않는다.

- 숙제 생성 원자성과 모든 재시도 쓰기의 멱등성 설계가 확정되고 테스트됨.
- 별도 승인 아래 현재 Supabase의 실제 데이터 유무·스키마·정책·함수·권한을 읽기 전용으로 확인함. 데이터가 존재할 때만 이관 매핑·원본 dump를 준비하며 불명확하면 원본을 유지함.
- 확정 기술 설계의 인증 교체·토큰 계약을 검증하고, 미확정 운영 정책인 데이터 보관·삭제·중단/손실 허용 시간을 결정권자가 승인함.
- 합성 데이터 리허설과 복원 시험이 통과하고 이전/롤백 runbook이 있음.
- 실데이터 접근과 운영 변경에 사용자가 별도로 승인함.

현재 판정: **로컬 합성 구현 준비 READY / 실제 마이그레이션·운영 전환은 미준비**. 원자성·멱등성·교차 권한의 목표 설계는 확정됐으나 구현/새 DB 테스트, 운영 정책 승인, 실제 데이터 확인과 백업/복원 리허설은 남아 있다. 새 DB 쓰기를 허용한 뒤 오래된 Supabase로 즉시 복귀하면 데이터가 유실될 수 있으므로 ADR-001 §9의 전환 시점별 복구 경계를 따른다.
