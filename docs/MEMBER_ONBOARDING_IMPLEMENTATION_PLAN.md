# 회원 등록·기존 기록 이전 실행 계획

작성일: 2026-09-20

상태: **S2~S4 구현·로컬 검증·운영 적용 완료 / S5 파일럿 대기**. 신규·기존 회원 등록, 선택적 원문 이전, 멱등 RPC, 강사 소유권, 회원 상세·다음 수업 조회를 구현했다. CSV·파일/OCR·패키지 재등록은 검증 전 확장하지 않는다.

운영 적용일: 2026-09-20  
적용 migration: `20260920115204_member_onboarding_imports.sql`  
Production: `https://instructor-sync-three.vercel.app`

## 1. 검토 결과와 근거

원장·기획, 앱·프론트엔드, 백엔드 관점의 에이전트 검토를 교차 비교했다. 원장 관점은 실제 인터뷰가 아닌 가상 사용 상황 검토다. 현재 타깃은 원장 직강 소형 PT/재활운동 지도 센터이며, 의료기관의 진료기록 이전이나 다강사 권한 체계까지 검증한 것이 아니다.

관련 기준: [제품 기준](PRODUCT_BASELINE.md), [데이터 무결성 기준](DATA_INTEGRITY_AND_POSTGRES_MIGRATION.md), [현재 작업 상태](../AUTO_BUILD_STATE.md).

현재 파일에서 확인한 사실:

- `app/app/members/page.tsx`: 신규 등록에서도 총 횟수·잔여 횟수를 별도로 입력한다. 이름·전화번호·목표는 필수이고, 저장 중 중복 클릭을 막는 상태가 없다.
- `lib/db.ts`: 회원 생성은 Supabase members 직접 insert다. 회원과 이전 기록을 함께 저장하는 원자적 계약은 없다.
- `lib/types.ts`: Member는 패키지 숫자 한 쌍을 가지며, SessionNote는 note와 created_at 중심이다. 이전 자료의 출처·실제 기록일·가져온 시각을 구분하는 타입은 없다.
- `lib/session-note.ts`: 4단계 노트는 `[SESSION_NOTE_V1]` 문자열 형식이며 과거 자유 텍스트와 공존한다. 이전 원문을 이 형식으로 위장하면 안 된다.
- 초기 members SQL에는 총 횟수·잔여 횟수의 범위 CHECK가 없다. 구현 때 전체 후속 migration과 운영 제약을 다시 확인한다.
- AUTO_BUILD_STATE에는 Production 배포가 보고돼 있으나 전체 실제 사용자 흐름은 미완료로 남아 있다. 대화상 앱 로그인 성공 보고는 있었고, Supabase 관리 콘솔의 인증 URL 설정 완료 여부는 확인되지 않았다.

앞선 제안에서 수정하는 점:

1. “핵심 요약만 이전”을 강제하지 않는다. 기존 텍스트 원문을 보관하고 필요한 요약만 선택적으로 작성한다.
2. 전화번호가 같아도 자동 병합하거나 패키지를 추가하지 않는다. 가족 공용 번호·동명이인·잘못된 입력을 사용자가 확인한다.
3. 패키지 재등록은 기록 가져오기와 별도 업무다. CSV 도입의 필수 선행 단계로 두지 않는다.
4. 기록 업로드 자체가 완료 기준이 아니다. 다음 수업에서 찾아보고 새 숙제 작성에 활용할 수 있어야 완료다.
5. 유료 전환 향상은 검증할 가설이다. 개발 완료나 긍정적인 인터뷰만으로 입증됐다고 기록하지 않는다.

역할 간 논점과 채택안:

| 관점 | 요구/이견 | 계획에서의 처리 |
| --- | --- | --- |
| 원장 역할 | 재입력은 줄이되 원본을 다시 확인할 수 있어야 함 | 원문 붙여넣기와 선택 요약, 나중 추가 허용 |
| 기획자 | 첫 사용 검증 전에 일괄 이전 범위를 키우면 안 됨 | 한 회원 이전→실제 수업 활용→파일럿 후 형식 선택 |
| 앱 개발자 | 저장 단계 실패 시 회원을 중복 생성하면 안 됨 | 등록 중 선택 기록까지 입력하면 최종 저장 하나, 등록 완료 후 추가는 별도 기록 요청 |
| 프론트엔드 | 모바일 모달에 모든 필드를 쌓으면 작성 어려움 | 단계별 입력, 모바일 전체 화면 형태, 명확한 저장 경계 |
| 백엔드 | 부분 실패·재시도·원문 정정의 계약 필요 | 요청 ID·소유권·원자 저장·원문 보존 및 정정 이력 |

CSV 부분 성공은 백엔드 검토의 후보였으나, 첫 버전에서는 작은 배치의 전체 원자 저장을 채택한다. 잘못된 행은 확정 전에 수정하거나 제외하며, 실행 중 오류는 배치 전체를 되돌린다. 큰 파일의 부분 성공·행별 재개는 별도 설계 대상으로 남긴다.

## 2. 사용자 흐름과 입력 계약

진입 버튼은 `+ 회원 등록`. 첫 선택은 `신규 회원` / `기존 수강 회원`이며 두 선택의 뜻을 한 문장씩 표시한다.

| 흐름 | 입력 및 동작 | 저장 결과 |
| --- | --- | --- |
| 신규 회원 | 이름·연락처·목표, 등록 횟수, 선택 만료일 | 총 횟수=잔여 횟수=등록 횟수. 잔여 입력란 없음 |
| 기존 수강 회원 | 현재 이용권의 원래 등록 횟수·현재 잔여 횟수·잔여 기준일, 기본 정보 | 현재 이용권의 시작 상태를 저장. 평생 누적 등록 횟수로 해석하지 않음 |
| 기존 수강 회원의 기록 이전 | 선택: 기존 기록 붙여넣기, 출처, 기록일/기간, 핵심 메모 | 강사 전용 이전 자료로 저장. 실제 수업·숙제 제출로 집계하지 않음 |
| 이미 앱에 있는 회원 | 회원 상세 → 기존 기록 추가 | 기존 회원 ID에 자료를 추가. 회원·이용권은 새로 생성하지 않음 |
| 앱 회원의 새 이용권 구매 | 별도 패키지 재등록 흐름 | 기존 기록 이전과 구분. 정책·이력 설계 후 별도 구현 |

기존 기록은 등록 시 건너뛸 수 있고 나중에 추가할 수 있다. 이름·연락처·목표 필수 정책은 현재와 같이 유지하되, 실제 파일럿에서 모르는 목표를 억지 입력하는 문제가 발견되면 별도 제품 결정으로 조정한다.

이전 자료 폼 제안:

- 기존 기록 원문: 메모장·노션·카카오톡에서 해당 회원에 필요한 텍스트만 붙여넣기.
- 출처: 직접 작성 / 기존 메모 / 대화 기록 / 기타. 외부 계정 연결 없이 작성자 선택.
- 기록일 또는 기간: 선택. 모르면 `날짜 미상`으로 표시하며 가져온 날짜를 수업 날짜로 사용하지 않는다.
- 핵심 요약: 선택. 최근 운동, 당시 반응, 현재 주의점, 다음에 확인할 내용을 자유롭게 작성. 과거 날짜의 주의점에는 시점을 표시한다.
- 저장 전 미리보기: 대상 회원과 원문·요약·날짜를 확인. 원문을 다섯 개 필드에 다시 입력하게 하지 않는다.

기록이 없는 회원도 등록할 수 있어야 한다. 과거 기록은 기록 당시 정보이므로 현재 상태를 자동 단정하거나 새 숙제로 자동 발행하지 않는다.

## 3. 단계와 선행 조건

| 단계 | 우선순위 | 선행 조건 | 이 단계가 필요한 이유 | 완료 산출물 |
| --- | --- | --- | --- | --- |
| S0 현재 운영 흐름 확인 | P0 | 없음 | 기반 인증·저장이 실패하면 이전 기능 오류와 구별 불가 | 운영 핵심 흐름 결과표 |
| S1 기록 샘플·입력 계약 확정 | P0 | S0와 병행 가능 | 실제 기록 형식 없이 CSV/OCR부터 만들면 재작업 | 비식별 예시, 입력 규칙, 화면 문구 |
| S2 안전한 저장 계약 | P0 | S1 | 원자성·중복 방지 없이 등록 화면만 만들면 데이터 오염 | additive migration 초안, RPC·RLS·실패 테스트 |
| S3 신규/기존 등록 + 원문 이전 | P0 | S2 | 한 명을 정확히 이전하는 최소 기능 확보 | 등록·미리보기·저장·재시도 흐름 |
| S4 다음 수업에서 활용 | P0 | S3 | 저장한 기록을 찾을 수 있어야 도입 가치 발생 | 상세·수업 화면의 이전 자료 조회 |
| S5 운영 파일럿 | P0 | S0~S4 | 실제 업무량·오연결·활용을 확인 | 관찰 결과, 수정 항목, 다음 단계 판단 |
| S6 CSV 일괄 이전 | P1, 조건부 | S5에서 표 자료 수요 확인 | 회원 수가 많을 때 반복 입력 감소 | 열 매핑·미리보기·일괄 저장·결과표 |
| R 패키지 재등록 | 별도 트랙 | 횟수·이월·만료 정책 확정 | 새 구매 내역을 보존 | 이용권 이력 설계·재등록 흐름 |
| S7 파일/OCR/AI | 후속, 조건부 | S5/S6에서 반복 수요 확인 | 사진·PDF 등 텍스트 이전으로 해결 못 한 문제 대응 | 별도 범위·비용·정확도 검토 |

P0는 이 기능을 안전하게 출시하는 데 필요한 순서이며, 모든 기존 서비스 기능을 다시 개발한다는 뜻이 아니다. S1의 조사·화면 계획은 S0와 병행할 수 있지만 실제 고객 데이터 이전은 S0와 저장 검증을 통과한 뒤 진행한다.

## 4. 단계별 작업 명세

### S0 — 운영 기반 확인

- 담당: 개발자. 사용자: 이메일 인증 링크 열기, 실제 휴대폰·카카오톡 확인.
- 새 계정 인증→로그인→회원→세션 노트→숙제→공개 링크 제출→수정 불가→대시보드/케어 큐를 합성 데이터로 확인한다.
- Supabase Auth Site URL·허용 callback과 최신 배포를 확인한다. 앱 로그인 성공과 관리 콘솔 로그인 성공을 구분한다.
- 두 테스트 강사 간 회원·기록 격리와 390px 화면을 확인한다. 실제 고객 기록은 테스트에 사용하지 않는다.
- 완료: 실패/미검증 항목과 담당자가 명시되고, 인증·저장·소유권 P0 실패가 없어야 신규 이전 기능 운영 검증으로 진행한다.

### S1 — 현장 자료와 화면 계약

- 사용자: 실제 원장에게 기존 기록 도구, 회원 수, 기록을 찾는 방식, 포기하기 싫은 항목을 확인한다. 공유할 자료는 가상 데이터로 재작성하거나 식별정보를 제거한다.
- 기획: 짧은 운동 메모, 날짜별 수업 목록, 표 형식 회원목록 예시를 비교한다. 원문 보존으로 충분한 것과 날짜별 검색이 꼭 필요한 것을 구분한다.
- 프론트: 등록 유형 선택→입력→이전 자료 선택→미리보기→회원 상세의 동선을 390px 기준으로 확정한다.
- 미확정 정보의 처리도 명시한다. 예를 들어 기존 이용권 총 횟수를 모르면 숫자를 만들어 넣지 않고 등록을 보류하거나, 파일럿 결과에 따라 '미상' 지원을 별도 설계한다.
- 완료: 신규/기존/기존 앱 회원의 예시 데이터 및 기대 결과가 각 1개 이상 있고, 필수·선택·날짜 미상·중복 후보 처리 문구가 합의돼 있다.

### S2 — 저장·권한·복구 계약

- 현 Supabase를 유지한다. 기존 Member 필드와 SessionNote V1을 일괄 변환하지 않는다.
- 제안 모델: 별도 `member_import_records`에 회원·소유 강사, 원문, 선택 요약, 출처, 선택 기록 기간, 가져온 시각, 요청 ID를 둔다. 명칭과 최종 컬럼은 구현 직전 관련 SQL 검토 후 확정한다.
- 이전 요약은 최초 버전에서 파생 초안이 아닌 강사가 확인한 텍스트다. 수정 시 원문을 조용히 덮어쓰지 않고 정정 관계/이력을 남기는 방식을 정한다.
- 새 회원+선택 이전 자료는 한 트랜잭션으로 저장한다. 기존 회원에 자료만 추가하는 경로는 소유권을 다시 검증한다.
- UI와 RPC 양쪽에서 정수·범위를 검사한다: 총 횟수≥1, 0≤잔여≤총 횟수. 신규 모드는 서버에서 잔여=총 횟수를 계산한다.
- 기존 데이터에 제약을 추가하기 전 위반 여부를 읽기 전용으로 확인한다. 문제가 있으면 보고하며 숫자를 임의 수정하거나 삭제하지 않는다.
- 같은 요청 ID·같은 내용의 재시도는 같은 결과를 반환하고, 같은 ID·다른 내용은 충돌로 거절한다. 중복 탭·타임아웃 후 재시도를 포함한다.
- RLS 및 RPC는 로그인한 강사 자신의 회원만 허용한다. anon과 공개 숙제 RPC에는 이전 기록 조회 권한을 추가하지 않는다.
- 텍스트 길이·요청 크기 상한을 명시하고 일반 텍스트로 렌더링한다. 원문/연락처를 로그·분석 이벤트에 남기지 않는다.
- 완료: 타 강사 접근, 잘못된 회원 연결, 중간 실패 전체 롤백, 동시 재시도 중복 없음, 공개 링크 비노출 테스트 통과. migration과 안전한 비활성화·복구 절차가 검토돼 있다.

### S3 — 회원 등록과 텍스트 이전

- 기존 `app/app/members/page.tsx`, `lib/db.ts`, `lib/types.ts`에서 필요한 경계만 수정한다. 재사용할 폼/검증 로직만 작게 분리한다.
- 신규는 횟수 입력 하나, 기존은 현재 이용권 총/잔여/기준일을 입력한다. 전환 시 숨겨진 잔여 값이 신규 회원 저장에 섞이지 않게 한다.

### S6 — CSV 일괄 이전

- 실제 원본이 표일 때만 진행한다. CSV 회원목록과 자유 텍스트 수업 기록은 서로 다른 자료이며, 모든 파일을 회원목록 양식으로 억지 변환하지 않는다.
- 첫 버전은 회원 기본 정보·현재 이용권·선택 기존 기록 열을 지원한다. 파일 예시와 열 이름 매핑을 제공한다.
- 현재 화면의 Free 5명 제한과 import 허용 건수를 먼저 일치시킨다. 상한과 초과 대상은 미리보기 전에 안내하고, CSV 우회 등록이 생기지 않도록 같은 서버 규칙을 적용한다. 제한/가격 변경은 별도 제품 결정이다.
- 흐름: 파일 선택→열 매핑→행별 검증→회원 연결 후보 확인→변경 예정 내용 확인→확정→행별 결과.
- 기존 회원이 감지되면 건너뛰기 / 사용자가 대상 지정 후 기록만 추가 / 다른 사람으로 신규 생성 중 선택한다. 기존 기본 정보·잔여 횟수는 자동 덮어쓰지 않는다.
- 동일 파일·동일 행 재실행 중복을 막는 배치/행 식별자를 둔다. 첫 버전의 규모 상한을 S1 자료로 정하고, 상한 내 한 배치 원자적 저장을 우선 검토한다.
- 같은 요청의 재시도는 기존 배치 ID를 재사용한다. 새 배치 ID로 동일 파일을 다시 올리는 경우에도 강사 범위의 이전 처리 이력을 대조해 경고한다. 동일 원문이라는 이유만으로 서로 다른 회원의 기록을 자동 제거하지 않는다.
- 범위를 넘는 대용량 비동기 작업은 별도 설계한다. 부분 성공을 허용하려면 성공/실패 행과 재시도 계약부터 확정한다.
- 입력 오류: 한글 인코딩, 따옴표·쉼표·줄바꿈, 전화번호 앞자리 0, 빈 값, 잘못된 날짜, 중복 행. 결과 CSV를 내려받게 되면 수식 실행 방지도 검사한다.
- 완료: 미리보기 건수와 저장 건수 일치, 확정 전 DB 변경 없음, 재시도 중복 없음, 강사 간 격리, 실패 시 기존 자료 무변경.

### R — 패키지 재등록 별도 트랙

- 앞선 '잔여 횟수에 새 횟수를 더한다'는 설명은 미확정 제안이다. 기존 잔여 이월, 새 이용권 시작일·만료일, 유효 이용권 복수 개 허용을 먼저 정한다.
- 수업 메모 작성이 출석/횟수 차감과 같은 사건인지도 분리해 결정한다. 메모 저장만으로 자동 차감하지 않는다.
- 필요가 확인되면 이용권·변경 이력을 설계하고 잔여 숫자를 원자적으로 갱신한다. 가져온 기록 건수로 소진 횟수를 추정하지 않는다.
- CSV를 기다릴 필요도, CSV가 이 기능을 기다릴 필요도 없다. 같은 잔여 계산 계약을 공유하는 부분만 의존성을 관리한다.

### S7 — 파일·OCR·AI 검토 조건

- 먼저 원본 보관만으로 요구가 해결되는지 평가한다. 파일은 강사 전용 접근, 용량·형식 제한, 보관·삭제·내보내기 정책과 운영 비용을 설계한 뒤 도입한다.
- 반복되는 사진/PDF 이전 수요가 확인되면 OCR/AI 추출을 '확인 전 초안'으로 제공하는 방안을 검토한다. 원문 근거를 함께 보여주고 날짜·무게·횟수·회원 연결을 사람이 확인한다.
- 자동 진단·운동 처방·과거 이력 추정·확인 없는 저장은 이번 범위에 포함하지 않는다. AI 외부 전송은 데이터 처리 조건을 별도 검토한다.

## 6. 변경·운영·검증 경계

- 기존 미커밋/삭제/미추적 작업을 보존한다. 새 프로젝트·인증 교체·대규모 리팩터링을 하지 않는다.

- 오류 이전 취소는 해당 배치만 식별하고 이후 생성된 기록과 관계를 검사하는 별도 절차다. 이미 활용된 회원과 수업을 연쇄 삭제하지 않는다.
- 완료 상태는 `계획됨 / 구현됨 / 로컬 검증됨 / 운영 적용됨 / 실제 사용자 검증됨`으로 기록한다. 이 문서의 모든 개발 단계는 현재 계획됨이다.
