# 운동숙제 제품 기준

> 문서 상태: **현재 제품 결정의 단일 기준**  
> 기준일: 2026-09-12  
> 구현 여부는 별도 표시하며, 가격·시장 검토·핸드오프보다 이 문서가 우선한다.

## 상태 표기

- **확정**: 현재 제품 범위와 작업 판단에 적용한다.
- **검증 중**: 고객·운영·실기기 또는 실제 데이터로 확인해야 하는 가설이다.
- **제안**: 논의 후보이며 구현 또는 판매 약속이 아니다.
- **폐기**: 현재 운동숙제 기준으로 사용하지 않는다.
- 기능 상태는 **구현됨 / 로컬 검증됨 / 실환경 검증됨 / 운영 적용됨**으로 따로 쓴다.

## 초기 구매자와 사용자

- **확정 — 구매자:** 원장이 직접 수업하고 구매 결정도 하는 1인 PT 또는 소형 스튜디오.
- **확정 — 강사 사용자:** 초기에는 센터당 원장 계정 1개만 지원한다.
- **확정 — 회원 사용자:** 앱 설치나 회원 계정 없이 강사가 보낸 개별 URL을 연다.
- **현재 제외:** 여러 강사, 직원 역할, 회원 인계, 조직 단위 소유권, 지점 통합 관리.

## 핵심 문제와 가치

강사가 카카오톡으로 숙제를 보내도 회원의 수행 여부와 어려움이 대화방에 흩어져 다음 수업 전에 찾기 어렵다. 운동숙제의 현재 가치는 숙제 작성·링크 전달·회원 반응·다음 수업 확인을 하나의 짧은 흐름으로 묶는 것이다.

- **확정:** “회원에게 카톡으로 숙제를 보내고, 남긴 말을 다음 수업 전에 바로 확인한다”가 핵심 기능 가치다.
- **검증 중:** 이 흐름이 강사의 준비 시간을 줄이고 회원의 관리받는 느낌과 반복 사용을 높이는가.
- **검증 중:** 장기적으로 패키지 만료 후 재등록에 긍정적 영향을 주는가.
- **폐기:** 검증 전에 “재등록률을 올린다”를 입증된 결과로 표현하는 것.

## 핵심 사용자 흐름

1. 강사가 회원을 선택하고 1~3개 운동, 수행 기준, 이유를 입력해 숙제를 만든다.
2. 강사가 생성된 카카오톡 문장과 URL을 복사해 직접 보낸다.
3. 회원이 `/h/[token]`을 열어 운동을 확인하고 완료 또는 못함을 선택한다.
4. 회원이 통증 여부와 짧은 메모를 같은 제출 흐름에서 남긴다.
5. 강사가 회원 상세·숙제 상세·다음 수업 화면에서 원문 기록을 확인한다.
6. 강사는 기록을 다음 수업 대화와 재등록 상담 준비에 활용한다.

카카오톡 자동 발송이나 전송 성공 추적은 이 흐름에 포함되지 않는다.

## 첫 10개 센터 무료 도입 목표

- **확정 — 초기 학습 목표:** 원장 직강 조건에 맞는 첫 10개 센터에 무료로 도입해 반복 사용과 운영 부담을 관찰한다.
- 무료 도입은 매출 성과가 아니라 문제 적합성, 활성화, 기록 신뢰성, 지원 비용을 배우기 위한 단계다.
- 센터별 시작일, 사용 회원 수, 숙제 발송 수, 응답 수, 강사 확인 여부, 지원 시간을 동일한 정의로 기록한다.
- **미확정:** 무료 기간, 회원 수 상한, 방문/원격 온보딩 범위, 종료 조건, 이후 가격과 유료 전환 조건.
- 이전 문서의 “10곳 미팅 제안”, “3곳 14일 파일럿”, 특정 날짜·가격은 참고 가설이며 이 목표를 대체하지 않는다.

## 초기 1계정 센터 범위

- 하나의 센터 계약 범위에 원장 본인 강사 계정 1개를 둔다.
- 그 계정이 자신의 회원, 숙제, 수행 기록, 수업 메모만 소유한다.
- 회원은 강사 계정이나 센터 데이터에 로그인하지 않는다. 숙제별 제한 토큰으로만 접근한다.
- 원장 퇴사·계정 이관·공동 소유·직원별 권한·감사 로그는 초기 범위가 아니다.

## 현재 포함 기능

| 기능 | 코드 상태 | 검증 경계 |
| --- | --- | --- |
| 강사 이메일 인증과 보호 라우트 | 구현됨 | 실제 계정·운영 환경 미검증 |
| 회원 등록·조회·수정 | 구현됨 | 계정 간 격리 실환경 미검증 |
| 1~3개 동작 숙제 작성과 링크/문장 복사 | 구현됨 | 숙제+동작 생성 원자성 미충족 |
| 회원 매직링크 열기, 만료·회수 판단 | 구현됨 | 운영 DB와 실기기 미검증 |
| 완료/못함·통증·메모 제출 | 원자적 RPC 코드와 로컬 DB 테스트 있음 | 요청 멱등성 없음, 운영 적용 미검증 |
| 회원/숙제 기록, 다음 수업 문장, 재등록 준비 카드 | 구현됨 | 현장 사용성·성과 미검증 |
| 음성 코치와 데모 모드 | 실험 기능 구현됨 | 판매 필수 기능 아님, 모바일 전 구간 미검증 |

## 현재 제외 기능

- 다강사·다지점·조직 역할 및 회원 이관
- 카카오톡 자동 발송, 알림톡, 전송 성공 확인
- 결제·구독·세금계산·서버 강제 사용량 제한
- 실시간 통증 모니터링, 의료 판단, 응급 대응 보장
- 화면 잠금이나 앱 전환 중 백그라운드 음성 지속 보장
- 자체 PostgreSQL로의 실제 이전과 Supabase/Auth 제거
- 소원 앱 기능, 강의 PDF 분석, FastAPI/LangChain 파이프라인

## 성공 지표 정의

지표는 합성·데모 데이터를 제외하고, 같은 기간과 동일한 분모로 계산한다.

| 지표 | 정의 | 상태 |
| --- | --- | --- |
| 센터 활성화율 | 무료 도입 센터 중 실제 회원에게 숙제 1개 이상을 보낸 센터 비율 | 검증 중 |
| 링크 오픈율 | 유효하게 공유된 숙제 중 회원이 1회 이상 연 숙제 비율 | 검증 중 |
| 기록률 | 열린 숙제 중 완료/못함 제출이 1회 이상 저장된 숙제 비율 | 검증 중 |
| 피드백 작성률 | 제출 중 통증 또는 메모가 포함된 제출 비율 | 검증 중 |
| 다음 수업 활용률 | 응답이 있었던 회원의 다음 수업 중 강사가 기록을 확인·활용했다고 남긴 비율 | 측정 방식 미확정 |
| 주간 반복 센터율 | 한 주에 숙제를 보낸 센터 중 다음 주에도 보낸 센터 비율 | 검증 중 |
| 지원 시간 | 센터별 온보딩·문의·복구에 든 사람 시간 | 검증 중 |
| 14일 내 재등록률 | 관찰 대상 패키지 만료 후 14일 내 재결제한 회원 / 관찰 가능한 만료 회원 | 장기 가설; 인과 성과 아님 |

목표 수치, 관찰 최소 표본, 비교군, 결측 처리, 재등록 귀속 규칙은 아직 확정하지 않았다.

## 결정 상태 요약

### 확정

- 원장 직강 소형 센터, 센터당 강사 1계정, 회원 무계정 링크 접근.
- 수동 카카오톡 복사 전달과 다음 수업 전 회원 원문 확인이 핵심 흐름.
- 첫 10개 센터 무료 도입을 학습 목표로 삼는다.
- 개인정보·소유권·저장 신뢰성은 일정과 기능 확장보다 먼저 통과한다.
- 자체 PostgreSQL은 장기 방향이지만 이번 기준 정리에서는 구현을 시작하지 않는다.

### 검증 중

- 원장이 기존 카카오톡보다 이 흐름을 반복 사용할지.
- 회원이 별도 로그인 없이 기록을 충분히 남길지.
- 다음 수업 준비 시간, 상담 품질, 재등록 관찰 지표가 개선될지.
- 무료 센터의 지원 부담과 유료 의사가 지속 가능한지.

### 제안

- 무료 파일럿 기간·회원 수 제한, 유료 전환 방식, 가격.
- 음성 코치의 기본 제공 여부와 별도 실험 처리.
- 향후 다강사·조직 기능과 카카오 자동화.

### 폐기

- 소원 앱과 과거 강의 분석 제품을 이 저장소의 현재 제품 기준에 함께 두는 것.
- 실증 전 재등록 상승, 자동 상담, 백그라운드 오디오를 판매 완료 기능으로 약속하는 것.
- 초기 1계정 범위에서 다강사 센터의 소유권·인계 문제를 해결했다고 간주하는 것.

## 미확정된 제품 결정

- 무료 도입 기간, 센터/회원 한도, 중단·졸업 조건.
- 유료 가격, 과금 단위, 부가세·환불·결제 수단.
- 강사가 회원 기록을 확인했다는 증거와 통증 기록 대응 책임.
- 데이터 보관·삭제·내보내기 정책, 개인정보 동의 문구.
- 음성 코치 출시 여부와 지원 기기 범위.
- 성공 지표 목표값, 최소 표본, 재등록 효과 판정 설계.
- 실제 호스팅·메일 제공자와 운영 계약. 인증·DB 도구·전환/롤백 기술 방식은 [기술 결정](POSTGRES_ARCHITECTURE_DECISION.md)에서 확정했으며 구현·운영 적용은 아직 아니다.
