## 0. 목적과 적용 규칙

회원이 중요하게 생각하는 일상 활동의 변화를 같은 조건으로 기록하고, 원장이 그 기록을 근거로 다음 수업을 설명하도록 만든다. 건강 점수·자세 교정률·치료 효과 판정은 만들지 않는다.

현재 프로젝트 `C:\Users\tmd31\instructor-sync`를 이어서 사용한다. 실제 파일, Git 상태, 테스트, 운영 검증을 문서보다 우선한다. 기존 modified/deleted/untracked 파일은 사용자 작업으로 취급한다. 새 프로젝트, 인증 교체, Supabase 제거, 기존 migration 수정·삭제, reset/clean, 대규모 리팩터링·의존성 업데이트를 하지 않는다.

관련 기준: [제품 기준](PRODUCT_BASELINE.md), [데이터 무결성](DATA_INTEGRITY_AND_POSTGRES_MIGRATION.md), [현재 상태](../AUTO_BUILD_STATE.md), [회원 등록 계획](MEMBER_ONBOARDING_IMPLEMENTATION_PLAN.md).

이 계획의 단계는 기존 EXECUTION_CONTROL 단계 번호를 대체하지 않는다. 가격·무료 기간·운영 권한을 확정한 문서로 해석하지 않는다. 구현 요청 후 일반 코드·테스트는 진행하되, 운영 적용은 해당 대화의 사용자 권한을 확인한다. 이미 승인된 안전한 배포를 다시 승인받을 필요는 없다.

## 1. 현재 기준선과 이전 보고에서 보완할 점

- main에 다수 미커밋·미추적 작업이 있다. 현재 핵심 기능 파일도 untracked이므로 Git diff만으로 변경 범위를 파악하지 않는다.
- 신규/기존 회원 등록, 원문 이전, 4단계 노트, 숙제·공개 제출·완료 후 수정 차단이 운영에서 확인됐다. 세부 근거는 AUTO_BUILD_STATE에 있다.
- `Profile.is_pro`와 회원 화면의 5명 제한이 있다. 25명 판매 계약·권한 프로비저닝·서버 한도는 별도 확인이 필요하다.
- 기존 불편함은 1~10의 '현재 느끼는 불편함'이다. 운동 직후·특정 부위 통증이라고 재해석하지 않는다.
- 숙제당 complete/cant와 pain 로그가 함께 생긴다. 로그 행 수를 제출 횟수로 세면 중복 집계된다.
- 기존 회원 이전 시 입력한 날짜가 화면에서 '날짜 미상'으로 보인 사례, 제출 완료 페이지 재방문 시 회원 메모 대신 '현재 느끼는 불편함'이 표시된 사례가 있다. 저장 결함인지 표시·브라우저 입력 문제인지 미확정이다.
- '못함' 실제 제출, 독립 계정 격리, 390px, 실제 카카오 브라우저, 복구 리허설까지 모두 통과했다고 이전 PASS 보고를 확대 해석하지 않는다.
- 과거 가격/시간 절감 추정은 실측이 아니다. 25명×주1.5회×4.33주라면 월 약162건이며 입력·확인·추가 관리 시간 모두 측정해야 한다.

## G2. 측정 계약 고정

강사가 회원과 대화하면서 입력하는 첫 버전이다. 회원이 직접 입력한 값과 대리 입력한 값을 구분한다.

### 목표별 기록

- 회원당 활성 목표 1~3개. 예: '같은 계단 두 층을 쉬지 않고 오르기'. 기존 end_state를 지우거나 자동 변환하지 않는다.
- 목표명 최대100자, 측정 조건 최대500자, 비교 방향(increase/decrease/none), 단위, 정의 버전을 저장한다.
- 첫 버전 측정 종류는 시간(초·분), 횟수, 거리(m), 회원이 보고한 활동 어려움(0~10)으로 한정한다. 어려움은 0=어려움 없음, 10=수행 불가라는 자체 기록 기준이며 정식 임상검사로 명명하지 않는다.
- 하나의 목표는 주 지표 하나를 갖는다. 예: '30분 앉기'의 목표치는 30분, 관측값은 같은 조건에서 실제 앉아 있던 시간이다.
- 회원이 정한 목표치와 최초 관측값을 분리한다. 최초값은 실제 입력해야 하며 과거 자유 메모에서 추출하지 않는다.
- 값은 유한한 0 이상 숫자, 어려움은 0~10 정수. 수행 불가/미측정은 별도 상태로 표시하며 자동으로 숫자0을 넣지 않는다.

### 재평가 입력

- 목표/정의 버전, 실제 측정일, 자동 저장 시각, 관측값 또는 미측정 이유, 출처(회원보고·강사측정), 입력자, 선택 메모(1000자 이내).
- '전보다 편해짐/비슷함/어려워짐/모르겠음'은 회원 의견으로 별도 저장하며 그래프를 보고 자동 선택하지 않는다.
- 동일 조건·단위·출처 시계열끼리 비교한다. 조건이나 측정 종류가 바뀌면 새 버전을 시작하고 기준점도 새로 받는다.
- 재평가 예정일은 기본14일 뒤, 강사가 변경 가능. 이는 운영 주기 제안이며 임상적 재평가 주기 권고가 아니다.
- 날짜가 지난 기록은 입력 가능하나 측정일과 입력일 모두 표시한다. 미래의 실제 측정일은 거절한다. 타임존 경계는 Asia/Seoul 기준으로 검사한다.

### 기존 불편함 기록

- 1~10과 원래 질문을 유지하고 새 0~10 활동 어려움과 합치지 않는다.
- '기록 시점 불편함' 보조 그래프로만 제공한다. 각 점에 날짜·숙제·완료/못함·메모를 연결한다.
- 숙제 하나를 관측 하나로 집계한다. 유효 숫자 없음은 결측으로 취급하고 pain 로그 없음=0으로 채우지 않는다.
- 통증 전용 새 지표는 후속 결정이다. 부위·상황·기간·척도 정의 없이 추가하지 않는다.

완료: 예시 JSON/TypeScript 계약과 입력 오류 문구, 0/결측/버전 변경/출처 변경 사례가 설명된다. SQL 작성 전 G2 규칙을 고정한다.

## G3. 안전한 저장

새 모듈 후보: lib/member-progress.ts(계산), lib/member-progress-data.ts(데이터 접근), lib/member-progress-types.ts(계약). 기존 lib/db.ts를 전체 재작성하지 않는다.

저장 단위는 목표/정의 버전, 평가 관측, 확인·후속 행동 이력이다. 실제 테이블·타입·인덱스는 Supabase/Postgres skills와 현재 schema 확인 후 설계한다. 이 문서는 SQL DDL 확정본이 아니다.

- 강사→회원→목표→관측 소유권을 DB에서 검사한다. 읽기와 쓰기 모두 다른 강사 ID 조합을 거절한다.
- 새 노출 테이블 RLS, 필요한 최소 GRANT, authenticated 소유자 전용 접근. anon은 새 평가·목표·보고서 테이블 접근 불가.
- 목표+최초 평가 생성은 단일 원자적 요청. 재평가와 정정도 각각 하나의 요청으로 저장한다.
- 요청 ID는 저장 시도 중 유지한다. 동일 ID/동일 payload는 같은 결과, 다른 payload는 충돌로 처리한다. 실패 뒤 폼 보존, 재시도 안전성을 확보한다.
- 평가 정정은 원본 삭제 없이 정정 사유·기존 ID를 연결한 새 버전으로 저장한다. 동시 정정은 버전 충돌을 반환한다. 유효 최신 정정만 집계한다.
- 목표 비활성화는 이력을 보존하며 활성3개 제한을 동시 요청에도 지킨다.
- CLI help 확인 후 migration new로 추가 migration을 만든다. 이미 적용된 migration을 수정하지 않는다.
- DB 연결 실패를 '기록 없음'이나 demo 성공으로 감추지 않는다.

필수 테스트: 두 강사 소유권 교차, anon 접근 거부, 부모 ID 변조, 원자 실패 rollback, 응답 유실 재시도, 동시 요청, payload 충돌, 잘못된 수치/단위/날짜, 목표 버전·정정의 교차 회원 연결 거절. PGlite 통과와 실제 독립 PostgreSQL 세션 동시성 검증은 구분한다.

## G4. 최초 평가·재평가 화면

진입: app/app/members/[id]/page.tsx의 '일상 목표와 변화' 섹션. 기존 회원 정보·이전 원문·수업 메모를 유지한다. 컴포넌트는 components/member-progress/에 분리한다.

1. '목표 추가' → 목표/조건/주 지표/단위/목표치 선택 → 최초 관측값과 출처 → 저장 전 대상 회원 확인 → 단일 저장.
2. '다시 기록' → 같은 조건을 위에 고정 표시 → 측정일/값/출처/회원 의견 → 저장. 일치하지 않는 조건은 기존 목표 덮어쓰기 대신 새 버전 안내.
3. '입력 정정' → 원래 기록 확인 → 사유와 수정값 → 원본 보존. 원본과 정정 표시를 명확히 한다.

## G5. 한 장 변화 보고서

구성: 회원 목표 → 같은 조건의 최초/최근 비교 → 관측별 그래프 → 회원 의견 → 강사의 다음 수업 계획.

집계 규칙:
- 기본 최근8주, 전체 기간 선택. 날짜 축 간격은 실제 날짜 비례. 관측이 없는 기간을 0이나 보간값으로 만들지 않는다.
- 관측0개: 최초 기록 CTA. 1개: 기준점만 표시. 2개 이상: 원자료 점과 시작/최근 차이 표시. '3개면 개선 입증' 규칙은 사용하지 않는다.
- 시작=같은 목표 버전의 가장 이른 유효 관측, 최근=가장 늦은 유효 관측. 측정일 동률은 저장시각 및 ID로 정렬한다. 선택 기간 이전 기준점은 날짜와 함께 별도 표시하고 기간 시작점으로 위장하지 않는다.
- 출처·조건·단위가 다른 값은 같은 비교선에 섞지 않는다. 호환 자료가 없으면 '같은 조건의 비교 기록이 없습니다'.
- 시간/횟수/거리 변화는 원단위로 표시. '10분 → 25분, 15분 증가'. 어려움/불편함은 '7 → 4, 3점 낮게 기록'. 퍼센트 회복률은 만들지 않는다.
- 중앙값·평균·AI 요약은 첫 버전에서 생략한다. 원자료의 급격한 악화도 숨기지 않는다.
- 어려움·불편함 그래프는 축 범위를 각각0~10, 1~10으로 고정한다. 단위·날짜·기록 수·출처를 함께 표시하고 색만으로 결과를 전달하지 않는다.
- 숙제 수행은 건강 결과와 별도 영역. 완료/못함/미응답을 분리하고 기존 수행률 정의·회수 처리 규칙을 재사용해 명시한다. 처방 세트·횟수를 실제 수행량으로 표시하지 않는다.

가벼운 SVG와 접근 가능한 수치 표를 우선 고려한다. 새 차트 라이브러리가 꼭 필요할 때만 작은 의존성 하나를 검토한다.

필수 테스트: 빈 자료/1개/2개, 0과결측, 입력순서와 측정일순서 차이, 동률, 정정 제외·반영, 조건·출처 변경, 기간 필터, 날짜 경계, 로그 중복, 상승/하락을 선택적으로 숨기지 않음.

## G6. 확인·다음 행동 연결

app/app/session/[memberId]/page.tsx에서 최근 비교를 짧게 보여주고 '회원과 확인' 및 '다음 수업 계획'을 남긴다. 기존 4단계 노트를 대체하지 않는다.

- 다음 행동은 자유 메모와 선택 예정일로 최소화한다. 자동 강도 조정이나 자동 진단은 없다.
- 새로 들어온 기록/재평가 예정은 통증 응급 경보와 구분한다. 처음에는 회원 상세·수업 화면에서 확인하고, 필요 시 기존 care-queue에 별도 이유로 추가한다.
- 숙제 미응답을 질병 악화·불성실 판정으로 바꾸지 않는다.

완료: 새 평가 → 미확인 → 해당 버전 확인 → 후속 계획 → 새 평가 시 다시 미확인 흐름 PASS.

## G7. 내보내기·복구·유료 파일럿 준비

- 강사 본인 회원 기록을 UTF-8 CSV로 내보내기. 단위·조건·출처·실제 측정일·기록일·정정 관계 포함. 전화번호는 기본 제외하고 CSV 수식 주입을 무력화한다.

- 운영 설정에 실제 백업 수단과 복구 가능한 범위를 확인한다. 테스트 환경에서 복원 후 행 수·소유권·정정 이력·표본 값을 비교한다. 백업 파일 생성만으로 복구 PASS라고 쓰지 않는다.
