1. Executive Summary

1.1 제품 한 문장 정의

운동숙제는 PT·필라테스 센터 원장이 운동 숙제를 빠르게 배정하고, 회원의 집 운동 결과를 AI가 정리하여 다음 수업까지 연결해 주는 B2B SaaS다.

원장은 회원에게 1~3개 운동을 간편하게 배정하고, 회원은 카카오톡 링크 하나로 운동을 확인·수행한다.

회원의 운동 완료 여부, 어려움, 통증, 메모가 누적되면 AI가 이를 정리해 원장에게 다음 수업 준비 가이드를 제안한다.

제품은 단순 운동 영상 서비스가 아니라 다음의 반복 업무를 연결한다.

수업 → 숙제 → 회원 수행 → 피드백 → AI 요약 → 원장 검토 → 다음 수업

1.2 핵심 가치 제안

원장

“숙제는 15초 만에 만들고, 회원의 운동 결과는 다음 수업 전에 확인한다.”

회원

“카카오톡 링크만 누르면 오늘 해야 할 운동이 나오고, 영상과 음성 안내를 따라 하면 된다.”

센터

“수업이 끝나도 운동 관리가 이어지고, 수업 사이에 남겨진 회원 기록을 다음 관리에 활용한다.”

1.3 세 가지 제품 기둥

핵심 기둥	기능	고객 가치
Fast Assignment	15초 숙제 생성	원장 반복 업무 최소화
Magic Link Experience	앱 없는 운동 수행·응답	회원 진입 장벽 최소화
AI Continuity	수행 결과 분석·다음 수업 준비	회원 관리의 연속성 확보

세 기둥 중 하나만 제공해서는 충분한 제품 가치를 증명하기 어렵다.

특히 빠른 숙제 생성은 첫 사용을 유도하는 기능이고, 회원 수행 결과가 다음 수업에 연결되는 경험은 반복 구독을 뒷받침할 핵심 가치 가설이다.

1.4 제품의 핵심 차별화 가설

기존 시장에는 운동 배정, 영상, 수행 기록, AI 프로그램 생성 서비스가 존재한다.

따라서 기능의 최초 제공을 주장하지 않는다.

운동숙제의 차별화 가설은 다음과 같다.

1. 종이·메모·음성 등 기존 기록 습관을 크게 바꾸지 않아도 된다.
2. 이전 운동과 루틴을 재사용해 숙제 생성 시간을 줄인다.
3. 회원이 새로운 앱 사용법을 배울 필요가 없다.
4. 회원 피드백을 단순히 저장하는 데 그치지 않고 다음 수업에서 확인할 정보로 구조화한다.
5. 운동 계획 변경 결정권은 원장에게 남긴다.

2. 고객 정의 및 문제 분석

2.1 Primary ICP — 초기 핵심 고객

원장이 직접 회원을 지도하는 1인 PT·재활 운동·소형 필라테스 스튜디오

초기 우선 고객 조건:

* 원장이 직접 수업한다.
* 기존 회원에게 집에서 할 운동을 안내하거나 배정한다.
* 회원과 카카오톡으로 자주 소통한다.
* 운동 숙제 안내를 별도의 유료 시스템 없이 수행한다.
* 회원 수와 수업 일정 때문에 관리 시간이 제한된다.
* 수업 후 회원 반응을 다음 수업에서 활용할 필요가 있다.

모든 센터를 고객으로 설정하지 않는다.

특히 숙제를 전혀 배정하지 않고 그 필요성도 느끼지 않는 센터는 초기 전환 대상에서 제외한다.

우선 이미 숙제를 주는 센터를 대상으로 기존 업무 개선 효과를 검증한다.

2.2 구매자와 사용자

역할	설명	주요 행동
원장	구매·결제 및 도입 결정자	구독 결정, 회원 관리, 숙제 배정
트레이너	운영 사용자	수업 기록, 운동 처방, 결과 검토
회원	최종 이용자	운동 확인, 수행, 피드백 제출
AI	보조 시스템	기록 구조화, 문구 초안, 결과 요약

초기 1인 스튜디오에서는 원장과 트레이너가 동일 인물일 수 있다.

2.3 기존 업무 프로세스

가설적 현장 시나리오:

1. 원장이 회원에게 운동을 지도한다.
2. 수업 내용을 기억하거나 노트에 기록한다.
3. 집에서 할 운동을 구두나 카카오톡으로 안내한다.
4. 필요하면 운동 영상 링크를 찾아 보낸다.
5. 회원은 안내를 기억하고 스스로 운동한다.
6. 다음 수업에서 원장이 운동 여부와 불편함을 질문한다.
7. 답변을 기억하거나 다시 메모한다.

이 과정이 실제 센터에서 얼마나 자주 발생하는지는 인터뷰와 관찰로 측정해야 한다.

2.4 기존 카카오톡 방식의 한계

카카오톡은 이미 편리한 소통 수단이다. 따라서 카카오톡 자체를 대체하려고 해서는 안 된다.

문제는 카카오톡이 운동 관리에 필요한 구조화된 데이터를 자동으로 만들어주지 않는다는 점이다.

예상 문제 A — 숙제 정보가 비구조적임

운동명, 횟수, 세트, 주의사항, 영상 링크가 개별 채팅에 섞여 있을 수 있다.

예상 문제 B — 수행 결과가 불명확함

회원이 메시지를 읽었다는 사실만으로 운동을 수행했는지 알 수 없다.

예상 문제 C — 다음 수업에 활용하기 어려움

이전 대화를 다시 찾아보거나 회원에게 반복해서 물어봐야 할 수 있다.

예상 문제 D — 반복 안내 비용

회원마다 비슷한 운동 설명을 반복하는 경우 업무 부담이 발생할 수 있다.

이 네 가지는 검증해야 할 문제 가설이다.

2.5 우선 해결할 문제

사업 MVP의 최우선 문제:

원장이 수업 외 운동을 배정하고 회원 결과를 다음 수업에 활용하는 과정이 분리되어 있다는 것.

이를 두 개의 측정 가능한 하위 문제로 나눈다.

* P0-A: 숙제 배정에 드는 시간과 반복 입력
* P0-B: 회원 응답을 다음 수업 전에 확인·정리하는 부담

회원의 운동 완료율 증가, 재활 효과 개선, 재등록률 증가는 후속 연구 또는 사업 가설로 분리한다.

4. 핵심 사용자 플로우

4.1 원장 플로우 A — 15초 빠른 숙제 생성

사용 조건:

* 회원이 이미 등록되어 있다.
* 운동 라이브러리 또는 이전 숙제 기록이 존재한다.
* 원장이 사전에 숙제 운동을 결정했다.
* AI 응답을 기다리지 않아도 기본값으로 숙제를 생성할 수 있다.

단계

STEP 1. 회원 선택

원장 메인 화면에서 최근 회원을 터치한다.

STEP 2. 숙제 만들기

회원 상세에서 ‘숙제 보내기’를 선택한다.

기본 화면에 다음이 표시된다.

* 지난 숙제
* 저장 루틴
* 자주 쓰는 운동

STEP 3. 운동 선택

지난 숙제나 루틴을 터치하면 1~3개 운동이 바로 채워진다.

운동명, 세트, 횟수, 시간, 영상, 주의사항의 기본값을 불러온다.

STEP 4. 예외만 수정

변경할 운동이 있으면 해당 슬라이드를 선택해 수정한다.

변경하지 않을 항목은 그대로 둔다.

STEP 5. 숙제 생성

‘숙제 만들기’를 터치하면 배정 정보와 회원 링크가 생성된다.

STEP 6. 카카오톡 공유

브라우저 공유 기능 또는 링크 복사로 카카오톡에 전달한다.

15초 정의

측정 시작: 회원이 선택된 상태에서 ‘숙제 보내기’를 누르는 시점
측정 종료: 유효한 회원 링크와 발송용 문구가 생성된 시점

카카오톡 앱에서 수신자를 선택하고 실제 전송하는 시간은 별도로 측정한다.

첫 회원 등록, 신규 운동 영상 제작, 음성 녹음, AI 오류 수정 등은 15초 측정 범위에 포함하지 않는다.

초기 목표

* 기존 루틴 재사용 숙제 생성: 중앙값 15초 이내
* 수업 기록부터 숙제 발송 준비: 60초 이내
* AI 구조화 오류 발생 시 별도 소요 시간 측정

모두 실험 목표이며 실측 성과가 아니다.

4.2 원장 플로우 B — 첫 수업 기록 후 숙제 생성

처음 사용하는 원장은 이전 기록이 없으므로 숙제 내용을 생성해야 한다.

입력 경로:

경로 1. 직접 검색

회원 선택 → 운동 검색 → 운동 3개 연속 추가 → 세트·횟수 확인 → 숙제 생성

경로 2. 자유 메모

“데드버그 10x3, 브릿지 12x2, 복압”

메모 입력 → AI 구조화 → 운동 블록 확인 → 숙제 생성

경로 3. 음성 입력

“데드버그 10회 3세트, 브릿지 12회 2세트. 데드버그는 복압 강조.”

음성 녹음 → STT → LLM 구조화 → 오류 확인 → 숙제 생성

경로 4. 수업 기록 활용

오늘 수업 기록 → 수행한 운동 목록 → 집에서 할 운동 선택 → 숙제 생성

중요한 업무 규칙

수업 기록은 숙제 배정의 필수 선행 조건이 아니다.

숙제만 빠르게 배정하고 싶은 원장은 수업 기록 없이 바로 숙제를 만들 수 있어야 한다.

수업 기록을 남기는 원장은 이를 숙제로 재사용할 수 있어야 한다.

두 경로는 공존한다.

4.3 회원 플로우

카카오톡 링크 수신
→ 링크 터치
→ 오늘 운동 확인
→ 운동 시작
→ 운동 영상 및 음성 안내
→ 세트별 완료 체크
→ 완료·중단·통증·메모 제출
→ 제출 완료 안내

회원은 별도 계정을 만들지 않는다.

4.4 다음 수업 연결 플로우

회원이 수행 결과 제출
→ 구조화된 데이터 저장
→ AI 결과 분석
→ 다음 수업 준비 카드 생성
→ 원장 대시보드에서 확인
→ 원장 검토
→ 수업 메모 또는 다음 숙제에 반영

AI가 제시한 다음 수업 준비 내용은 의사결정 지원 정보다.

운동 처방을 자동 확정하지 않는다.

5. 원장 UX 및 화면 명세

5.1 전체 화면 구조

5.2 화면 T01 — 회원 관리

목적

구성

상단:

* 검색
* 회원 추가
* 최근 회원

회원 카드:

* 회원 이름
* 최근 수업일
* 최근 숙제 상태
* 미확인 피드백 수
* 다음 수업 확인 필요 여부

주요 버튼:

* 다음 수업 준비

예시

김OO 회원
최근 숙제: 일부 완료
통증 보고: 있음
다음 수업 준비: 확인 필요

[숙제 보내기] [결과 확인]

UX 원칙

원장이 수업 직후 사용한다는 전제에서 회원 검색을 빠르게 제공한다.

불필요한 통계 그래프보다 다음 행동에 필요한 정보를 우선 배치한다.

5.3 화면 T02 — 수업·숙제 작업대

운동숙제의 가장 중요한 화면

상단

회원 이름
수업 기록 / 숙제 작성 탭
지난 수업 불러오기
저장 루틴

입력 도구

* 운동 검색
* 빠른 메모
* 음성 입력

운동 슬라이드

운동을 추가하면 각 운동이 카드로 생성된다.

카드 기본 정보:

* 운동명
* 영상 썸네일
* 세트 × 횟수
* 필수·선택
* 주의사항 유무

여러 운동을 가로 카드로 보여준다.

상세 내용을 모두 세로로 펼치지 않는다.

선택 운동 상세

선택된 운동에 대해서만 다음을 편집한다.

* 세트
* 반복 횟수
* 시간
* 휴식
* 좌우
* 운동 설명
* 코칭 문구
* 주의사항

하단 고정 액션

수업 기록 탭:

* 수업 저장
* 숙제로 만들기

숙제 작성 탭:

* 숙제 미리보기
* 숙제 생성

동작 규칙

1. 운동을 검색하고 추가해도 검색창이 닫히지 않는다.
2. 운동별 기본값을 자동으로 채운다.
3. 이전 운동을 복제할 수 있다.
4. 실수한 변경을 취소할 수 있다.
5. 수업 원본과 숙제 복사본을 별도 보존한다.
6. 운동이 3개를 넘더라도 데이터 구조상 처리 가능하도록 한다. 다만 MVP 기본 작성 UX는 1~3개 운동을 우선 최적화한다.
7. AI가 인식한 운동명이나 숫자가 불확실하면 확인 표시를 남긴다.
8. 저장 성공과 링크 발송 여부를 구분한다.

5.4 화면 T03 — 숙제 확인 및 공유

필수 요소

회원 이름
숙제 제목
운동 목록
운동별 목표량
숙제 목적 Why
주의사항
회원용 화면 미리보기

액션

* 숙제 생성
* 링크 복사
* 시스템 공유
* 수정하기

중요 정책

‘숙제 생성’과 ‘카카오톡 실제 전달’은 별개의 사건이다.

링크가 생성되었다는 사실만으로 회원이 숙제를 받았다고 기록하지 않는다.

자동 전송 기능이 없다면 실제 카카오톡 전달 여부는 별도 상태로 관리한다.

5.5 화면 T04 — 다음 수업 준비 카드

목적

원장이 다음 수업 시작 전에 회원의 최근 운동 기록과 확인할 사항을 짧게 파악한다.

표시 우선순위

1. 통증·이상 증상 보고
2. 운동 미완료 또는 중단
3. 회원이 직접 남긴 메모
4. 최근 숙제 참여 기록
5. AI가 생성한 확인 질문
6. 지난 수업과의 비교

예시

김OO — 다음 수업 준비

최근 숙제: 3개 중 2개 완료 보고
통증: 무릎 6/10 보고
회원 메모: “스쿼트 할 때 무릎 앞쪽이 불편했어요.”

AI 요약

“회원이 스쿼트 수행 중 무릎 불편함을 보고했습니다. 운동 수행 조건과 증상 발생 시점을 다음 수업에서 확인할 필요가 있습니다.”

확인 질문

“어느 구간에서 불편함이 발생했나요?”

원장 액션

[확인 완료] [수업 메모에 추가] [다음 숙제 참고]

안전 정책

AI는 통증의 원인을 진단하지 않는다.

운동 중 통증이 있다고 해서 특정 운동을 자동으로 금지하거나 새로운 운동을 처방하지 않는다.

필요한 확인 사항을 제안하고 최종 판단은 원장이 한다.

6. 회원 UX 및 매직링크 설계

6.1 매직링크 정의

회원에게 별도 앱 설치나 회원가입을 요구하지 않고, 고유 링크로 배정된 운동에 접근하도록 하는 방식이다.

예상 경로:

/h/{token}

토큰은 추측하기 어려운 무작위 값으로 생성한다.

보안 조건

* 토큰 원문을 DB에 그대로 저장하지 않는 구조 우선
* 서버에서 토큰 해시 검증
* 만료·회수·재발급 지원
* 유효하지 않은 토큰 접근 차단
* 다른 회원의 숙제 접근 방지
* 공개 페이지에 불필요한 개인정보 노출 금지
* 접근 횟수 제한 및 이상 요청 대응

매직링크는 별도의 신원 확인을 제공하지 않는 보유자 접근 방식이다.

링크를 전달받은 제3자가 접근할 위험이 있으므로 표시 정보와 토큰 정책을 최소 권한 원칙으로 설계한다.

6.2 화면 M01 — 운동 시작

구성

오늘의 운동
운동 개수
운동 목표량
영상 미리보기
담당 트레이너의 안내 문구
큰 시작 버튼

Why 표시 예시

“지난 수업에서 배운 움직임을 집에서도 가볍게 이어가기 위한 운동이에요.”

회원의 실제 목표와 원장 승인 문구를 반영한다.

추상적인 동기부여 문구보다는 왜 이 운동을 배정했는지 이해할 수 있는 설명을 우선한다.

6.3 화면 M02 — 운동 진행

화면 구성

상단:

* 운동명
* 시범 영상
* 운동 순서

중앙:

* 현재 세트 / 전체 세트
* 반복 횟수 또는 수행 시간
* 주의사항

하단:

* 세트 완료
* 일시정지
* 음성 다시 듣기
* 그만두기

PACE-FIT 기본 동작

운동 시작
→ 운동 설명
→ 세트 시작 안내
→ 운동 코칭 음성
→ 세트 완료
→ 휴식 안내
→ 다음 세트 또는 운동

회원의 운동 방식에 따라 시간 기반 또는 횟수 기반 진행을 지원한다.

세트 완료 버튼은 자기 보고 기록이다.

카메라나 센서로 실제 동작을 측정했다는 의미가 아니다.

6.4 화면 M03 — 수행 결과 제출

기본 입력

1. 오늘 운동을 얼마나 하셨나요?
    * 모두 완료
    * 일부 완료
    * 하지 못함
2. 운동 중 불편하거나 아픈 곳이 있었나요?
    * 없음
    * 있음
3. 통증이 있다면 어느 정도였나요?
    * 1~10점
4. 메모
    * 선택 입력

입력 UX

통증 없음 선택 시 통증 점수 입력을 요구하지 않는다.

통증 있음 선택 시 점수 선택을 제공한다.

메모는 필수가 아니다.

운동 결과 제출 시 화면에 명확한 완료 메시지를 표시한다.

데이터 해석

* 통증 0점: ‘없음’ 응답을 내부 데이터로 표현할 때 사용 가능
* 통증 1~10점: 회원이 통증이 있다고 선택한 후 보고한 값
* null: 통증 여부 또는 점수가 제출되지 않음

0과 null을 같은 값으로 취급하지 않는다.

6.5 중단 및 안전 UX

운동 중 언제든지 중단할 수 있다.

중단 시 이유 후보:

* 시간이 없음
* 너무 어려움
* 통증·불편함
* 다른 이유

회원에게 필수 운동이 배정되더라도 통증이 있는 상태에서 수행을 강요하지 않는다.

심한 통증이나 이상 증상이 보고되면 추가 운동을 권유하는 대신 중단 및 적절한 전문가 상담 안내를 제공한다.

7. AI 핵심 기능 상세 명세

7.1 AI 기능의 기본 원칙

AI는 운동 처방의 결정권자가 아니라, 원장의 기록·설명·검토 업무를 보조하는 시스템이다.

AI가 맡을 역할:

* 비구조적 입력을 구조화
* 회원에게 전달할 문구 초안 생성
* 실제 수집된 수행 결과 요약
* 원장이 확인해야 할 항목 선별
* 주간 기록 정리

AI가 맡지 않을 역할:

* 자동 질병 진단
* 재활 처방 자동 변경
* 회원 상태의 근거 없는 추정
* 실제 수행하지 않은 운동을 완료로 판정
* 사용자가 보고하지 않은 통증이나 증상 생성
* 원장 승인 없이 위험한 운동량 증가

7.2 AI-01 — 숙제 Why 초안 생성

목적

원장이 운동을 선택한 이유를 회원에게 이해하기 쉽게 전달하도록 돕는다.

입력 데이터

필드	설명
member_goal	회원이 밝힌 운동 목표
assignment_purpose	이번 숙제를 배정한 목적
exercise_list	선택된 운동 목록
trainer_note	원장의 수업 메모
previous_feedback	이전 숙제의 관련 응답
safety_note	원장이 지정한 주의사항

처리 과정

1. 회원과 숙제 정보 조회
2. 필요한 최소 필드로 AI 입력 구성
3. 입력 데이터에서 확인된 사실 추출
4. 회원용 설명 문구 생성
5. 사실과 일치하는지 검증
6. 원장에게 편집 가능한 초안 표시
7. 원장 승인 후 숙제에 반영

프롬프트 규칙

시스템 지시 핵심:

“당신은 트레이너의 운동 숙제 설명을 작성하는 보조 도구다. 제공된 운동 목적과 트레이너 기록만 사용한다. 진단, 치료 효과, 회복 속도, 운동 성과를 단정하지 않는다. 회원이 이해하기 쉬운 짧은 문장을 작성한다. 정보가 부족하면 일반적인 배정 목적 설명으로 제한하고, 없는 사실을 추가하지 않는다.”

출력 예시

입력:

* 회원 목표: 기본 코어 안정성 향상
* 운동: 데드버그, 브릿지
* 배정 목적: 수업에서 배운 동작 복습

출력:

“오늘 배운 코어 운동을 집에서도 천천히 복습해 보세요. 정확한 동작에 집중하고, 불편함이 있으면 무리하지 마세요.”

인터페이스

원장 작업대:

AI가 작성한 숙제 안내

[생성 문구]

[다시 생성] [직접 수정] [적용]

완료 기준

* 실제 입력에 없는 의료적 효능을 주장하지 않음
* 운동명과 배정 목적이 일치함
* 원장이 수정 가능함
* 승인 전 자동 발송하지 않음
* AI가 실패해도 기본 안내문으로 배정 가능

7.3 AI-02 — 다음 수업 준비 가이드

공모전 데모의 핵심 AI 기능

목적

회원이 남긴 수행 결과를 원장이 다음 수업에서 즉시 활용할 수 있게 한다.

입력 데이터

* 배정된 숙제 운동
* 운동별 계획 분량
* 수행 세션 로그
* 완료·미완료 자기 보고
* 통증 유무
* 통증 점수
* 회원 메모
* 기존 수업 기록
* 기존 회원 목표
* 이전 관련 피드백

처리 파이프라인

1단계. 데이터 수집

회원이 결과를 제출한다.

2단계. 정형 검증

운동 ID, 숙제 ID, 제출 시각, 점수 범위, 제출 상태를 검사한다.

3단계. 규칙 기반 우선순위 분류

예:

* 통증 보고가 있음 → 확인 필요
* 중단 기록이 있음 → 중단 사유 확인
* 여러 숙제에 응답이 없음 → 참여 여부 확인
* 완료했다고 보고함 → 결과 확인

통증 점수별 우선순위 기준은 서비스 운영 규칙으로 별도 검토한다. 임의의 점수 기준을 의료적 위험 진단으로 사용하지 않는다.

4단계. LLM 요약

원문과 정형 데이터를 바탕으로 다음 항목을 생성한다.

* 핵심 사실 요약
* 회원이 직접 보고한 문제
* 다음 수업에서 확인할 질문
* 원장이 판단할 필요가 있는 사항

5단계. 결과 검증

AI가 언급한 운동명, 횟수, 통증 점수, 메모가 실제 입력에 존재하는지 확인한다.

6단계. 준비 카드 생성

원장 대시보드에 표시한다.

7단계. 원장 검토

원장이 확인·수정·보류한다.

예시 데이터

숙제:

* 스쿼트 10회 × 3세트
* 브릿지 12회 × 2세트

회원 결과:

* 스쿼트 일부 완료
* 브릿지 완료
* 통증 6/10
* 메모: “스쿼트 중 무릎 앞쪽이 불편했어요.”

AI 출력

핵심 요약

“스쿼트는 일부 수행했고 브릿지는 완료했다고 보고했습니다. 스쿼트 수행 중 무릎 앞쪽 불편함을 6/10으로 보고했습니다.”

다음 수업 확인 항목

* 불편함이 발생한 운동 구간 확인
* 이전 수업과 동일한 증상인지 확인
* 스쿼트 수행 조건 및 중단 이유 확인

주의

“통증 원인과 운동량 변경은 담당 트레이너가 확인해야 합니다.”

절대 금지할 출력

* “무릎 연골 손상이 의심됩니다.”
* “다음 수업에서는 반드시 스쿼트를 중단하세요.”
* “운동량을 30% 늘리세요.”
* “이 운동을 하면 통증이 완치됩니다.”

출력 데이터 구조

* summary
* evidence
* review_questions[]
* attention_flags[]
* suggested_followup_note
* requires_trainer_review
* model_version
* generated_at

모든 핵심 분석은 어떤 원본 기록을 참고했는지 추적 가능해야 한다.

완료 기준

* 실제 제출 정보와 일치하는 요약 생성
* 통증·중단 상황을 누락하지 않음

7.4 데이터베이스 스키마 상세 설계

7.4.1 설계 원칙

운동숙제의 데이터베이스는 단순한 운동 기록장이 아니라 다음 업무를 연결하는 시스템이어야 한다.

수업 기록 → 숙제 배정 → 회원 수행 → 피드백 → AI 분석 → 강사 검토 → 다음 수업 반영

핵심 원칙은 다음과 같다.

1. 회원, 강사, 센터의 소유 관계를 명확하게 정의한다.
2. 수업 기록과 숙제 처방은 서로 다른 데이터로 저장한다.
3. 숙제 발행 시점의 운동 정보와 코칭 정보를 스냅샷으로 보존한다.
4. 회원의 실제 수행 주장과 시스템에서 관찰한 이벤트를 구분한다.
5. AI가 생성한 내용과 강사가 최종 승인한 내용을 분리한다.
6. 통증·불편함 기록은 누락 없이 추적하되, 불필요한 의료정보 수집은 피한다.
7. 다음 수업에 반영한 사항의 담당자와 근거를 기록한다.
8. 센터 간 데이터 접근을 차단한다.

기존 데이터베이스에 members, homework, homework_items, homework_submissions, member_progress_goals, session_notes 등의 구조가 존재했던 것으로 확인되었다.

그러나 다음 테이블 정의는 기존 운영 DB의 현재 상태를 의미하지 않으며, 고도화 MVP의 논리적 목표 스키마다.

실제 개발에서는 기존 테이블을 확인한 후 마이그레이션하거나, 새 프로젝트에서 동일한 역할을 갖는 테이블을 구현한다.

핵심 관계 제약

* 회원은 특정 센터에 소속된다.
* 회원은 하나 이상의 수업 기록을 가질 수 있다.
* 수업 기록 한 건은 여러 운동 항목을 가질 수 있다.
* 숙제 한 건은 MVP 기준 기본적으로 1~3개 운동을 포함한다.
* 숙제 한 건은 여러 운동 세션을 가질 수 있다.
* 운동 세션은 여러 세트 이벤트를 가질 수 있다.
* 피드백은 특정 숙제 및 필요시 특정 운동 세션과 연결된다.
* AI 결과는 근거가 된 원본 기록의 ID를 참조할 수 있어야 한다.
* 강사가 AI 제안을 실제 관리에 반영했다면 검토·승인 이력을 남긴다.

운동숙제의 ‘1~3개 운동’은 초기 고객 경험과 데모를 단순화하기 위한 MVP 제품 정책이다. 실제 운동 목록의 물리적인 데이터 모델에 영구적인 3개 상한을 강제할 필요는 없다.

7.4.4 수업 기록과 숙제의 분리

수업에서는 다음과 같은 운동을 수행했다고 가정한다.

{
  "session_exercise": {
    "exercise": "브릿지",
    "sets": 3,
    "reps": 15,
    "performed_in_class": true
  }
}

이를 숙제로 변환할 때 다음과 같이 조정한다.

{
  "homework_item": {
    "exercise": "브릿지",
    "sets": 2,
    "reps": 10,
    "required": true,
    "source_session_exercise_id": "original-id"
  }
}

이때 숙제 수정이 원본 수업 기록에 반영되어서는 안 된다.

수업 기록이 없더라도 강사는 운동 라이브러리 또는 저장 루틴에서 직접 숙제를 만들 수 있어야 한다.

7.6 매직링크 및 보안

7.6.1 기본 정책

매직링크는 회원이 로그인하지 않고 숙제를 이용하도록 하는 핵심 UX다.

예시:

https://exercisehomework.kr/h/{secure-token}

링크를 가진 사람은 해당 숙제에 접근할 수 있으므로 토큰 자체가 접근 권한을 제공하는 자격 증명이다.

필수 정책:

* 충분히 긴 암호학적 난수 토큰 생성
* 서버에는 토큰 원문 대신 해시 저장
* 만료 및 철회 지원
* 다른 회원 정보 접근 차단
* 링크 재발급 시 기존 링크 처리 정책 적용
* API 요청 횟수 제한
* 로그·분석 도구에 토큰 노출 최소화
* 민감정보가 링크 미리보기에 나타나지 않도록 처리
* 회원용 기능은 해당 숙제 조회 및 본인 제출로 범위 제한

민감한 건강정보를 다루므로 무기한 공개 링크를 기본으로 두지 않는다.

MVP에서는 만료 기간을 설정하고 강사가 재발급할 수 있도록 한다. 실제 기간은 파일럿 정책과 개인정보 검토를 통해 결정한다.

7.6.2 RLS 및 데이터 격리

최소 테스트:

* 센터 A 강사는 센터 B 회원을 조회할 수 없다.
* 센터 A 강사는 센터 B 숙제를 수정할 수 없다.
* 회원 공개 링크에서 강사 전용 데이터를 조회할 수 없다.
* 만료되거나 철회된 토큰은 접근할 수 없다.
* 숙제 생성 과정에서 운동 항목 저장이 실패하면 전체 생성이 실패한다.
* 동일 요청을 반복 전송해도 중복 숙제가 생성되지 않는다.
* 피드백 제출이 중복되더라도 정의된 정책에 따라 일관되게 처리한다.

공개 링크용 데이터 조회는 인증 우회가 아닌 허용된 데이터만 반환하는 서버 API 또는 제한된 RPC로 구현한다.

7.6.3 통증 및 개인정보

회원에게는 통증과 불편함을 기록하는 목적을 명확하게 안내한다.

통증 기록은 의료적 진단 결과로 취급하지 않는다.

AI 출력도 치료 처방이나 질환 진단을 대신하지 않는다.

데이터 저장·보관·삭제·접근 권한 및 동의 절차는 실제 국내 개인정보 관련 요건을 검토한 뒤 정한다.

8. AI 핵심 기능 상세 명세

8.1 AI 기능 우선순위

이번 공모전 MVP는 단순히 LLM API를 연결하는 것이 아니라, AI가 강사의 반복 업무와 판단 준비 과정에서 어떤 가치를 만드는지 보여줘야 한다.

핵심 기능은 다음과 같다.

기능	AI 역할	우선순위
운동 메모·음성 구조화	비정형 입력을 운동 데이터로 변환	P0
숙제 Why 초안	회원 목표·수업 내용을 바탕으로 설명 생성	P0
다음 수업 준비 카드	수행·통증·메모에서 확인할 항목 도출	P0
주간 운동 요약	여러 숙제 수행 결과를 기간별 정리	P1
운동 루틴 추천	기존 루틴에서 후보 제안	P1
자동 운동 처방 변경	AI가 강도·운동량 변경	MVP 제외

공모전의 대표 AI 킬러 기능은 ‘다음 수업 준비 카드’로 설정한다.

단순히 숙제를 자동 생성하는 것보다 회원의 반응을 다음 수업 준비에 활용하는 모습이 전체 서비스의 가치를 더 명확하게 보여주기 때문이다.

단, 이 기능의 실사용 가치와 안전성은 아직 검증되지 않았다.

8.2 AI 기능 A — 음성·메모 기반 운동 구조화

입력

강사의 원본 발화 또는 메모:

“김 회원 데드버그 10회 3세트, 브릿지 2분씩 2세트. 복압 유지 강조.”

처리

1. 필요하면 STT를 이용해 음성 전사
2. 운동명 후보 추출
3. 운동명 별칭 검색
4. 세트·횟수·시간 추출
5. 코칭 키워드 연결
6. JSON 구조화
7. 형식·범위·단위 검증
8. 강사 확인

출력 예시

{
  "exercises": [
    {
      "name": "데드버그",
      "exercise_id": "dead_bug",
      "sets": 3,
      "reps": 10,
      "duration_seconds": null,
      "coaching_keywords": ["복압"],
      "needs_review": false
    },
    {
      "name": "브릿지",
      "exercise_id": "bridge",
      "sets": 2,
      "reps": null,
      "duration_seconds": 120,
      "coaching_keywords": [],
      "needs_review": false
    }
  ]
}

ID는 운동 라이브러리에서 실제 매칭한 값으로 채운다.

UX 요구사항

* 음성 인식 결과를 원문과 함께 표시한다.
* 운동명이나 수치가 모호하면 해당 카드만 강조한다.
* 강사가 한 번의 조작으로 후보를 선택할 수 있어야 한다.
* AI 처리에 실패해도 수동 입력을 계속 사용할 수 있어야 한다.

완료 기준

입력 문장의 운동명, 세트, 횟수, 시간, 키워드를 구조화할 수 있어야 한다.

임의의 숫자 추정이나 운동 처방 변경은 허용하지 않는다.

⸻

8.3 AI 기능 B — 숙제 Why 초안 생성

목적

회원에게 단순히 운동 이름을 전달하는 것이 아니라 이번 숙제를 왜 해야 하는지 이해하기 쉬운 문장으로 제공한다.

입력 데이터

* 회원의 운동 목표
* 오늘 수업 운동
* 이번에 배정할 숙제
* 강사가 기록한 주요 주의사항
* 이번 숙제 배정 이유
* 이전 숙제 결과(존재하는 경우)

처리 규칙

AI는 새로운 운동 처방을 만드는 것이 아니다.

강사가 선택한 운동과 기존 목표를 바탕으로 숙제의 목적을 설명하는 짧은 문장을 생성한다.

출력 예시

회원 목표:

“일상생활에서 움직일 때 몸통을 안정적으로 유지하고 싶다.”

배정 운동:

* 데드버그
* 브릿지

AI Why 초안:

“오늘 연습한 몸통 안정화 운동을 집에서도 반복해 보세요. 무리하지 않는 범위에서 천천히 움직이며, 배운 자세를 다시 익히는 것이 이번 숙제의 목적입니다.”

원장님 화면

오늘의 숙제
데드버그     10회 × 3세트
브릿지       12회 × 2세트
[AI가 작성한 숙제 이유]
"오늘 배운 동작을 집에서도 반복해
 몸통 안정화 자세를 익혀보세요."
[수정] [다시 생성] [이대로 사용]

제약

* 증명되지 않은 신체 기능 개선을 보장하지 않는다.
* 통증이 있는 회원에게 무조건 수행하도록 지시하지 않는다.
* 강사가 제공하지 않은 진단명·병력을 추가하지 않는다.
* 강사의 수정·승인 전에는 발송 문장으로 확정하지 않는다.

⸻

8.4 AI 기능 C — 회원 통증·피드백 분석

목적

회원이 남긴 운동 수행 기록과 통증·어려움 메모를 강사가 빠르게 확인하도록 구조화한다.

입력 데이터

* 배정 운동
* 목표 운동량
* 회원이 표시한 수행 세트
* 완료·중단 여부
* 통증 여부 및 점수
* 통증 부위(선택 입력)
* 회원 메모
* 이전 관련 피드백

입력 예시

{
  "exercise": "브릿지",
  "prescribed_sets": 3,
  "reported_completed_sets": 2,
  "pain_score": 6,
  "pain_area": "허리",
  "member_note": "두 번째 세트부터 허리가 불편해서 그만했어요."
}

AI 처리

AI는 다음 정보를 추출한다.

1. 실제 보고된 수행량
2. 목표량 대비 차이
3. 회원이 보고한 불편함
4. 미확인 사항
5. 원장님이 다음 수업에서 물어볼 질문

출력 예시

[수행 결과]
브릿지 3세트 중 2세트 완료 보고
[주의가 필요한 피드백]
회원이 허리 불편함을 보고함.
통증 점수: 6/10
[다음 수업 확인 질문]
- 불편함이 시작된 시점은 언제인가요?
- 운동을 멈춘 뒤에도 불편함이 있었나요?
[강사 확인]
운동 지속 및 변경 여부는 담당 강사가 판단

중요한 제한

AI가 통증 점수만 보고 진단하거나 운동 강도를 독자적으로 조정하지 않는다.

통증 보고가 있으면 사실과 회원 원문을 우선 표시한다.

통증 정도에 따른 화면상의 강조나 검토 우선순위는 별도 규칙으로 정의할 수 있지만, 그것이 의료적 위험도 판정이라는 의미는 아니다.

8.5 AI 기능 D — 다음 수업 준비 카드

목적

이 기능이 운동숙제의 반복 구매 가치를 보여주는 핵심이다.

회원의 지난 숙제 수행 이력과 피드백을 다음 수업 시작 전에 한눈에 보여준다.

입력 데이터

* 회원 기본 목표
* 직전 수업 기록
* 최근 숙제 배정
* 숙제별 운동 목록
* 운동 세션 이벤트
* 완료·중단 보고
* 통증 및 메모
* 이전 강사 검토 결과

처리 흐름

회원 수행 결과 제출
→ 관련 숙제·피드백 저장
→ 서버에서 AI 분석 실행
→ 사실 요약 및 확인할 질문 생성
→ 다음 수업 준비 카드 저장
→ 회원 상세 및 최근 회원 목록에 표시

AI 분석이 실패하더라도 정형 데이터 기반 기본 카드는 표시해야 한다.

출력 화면

│                                    │
│ 회원 피드백                         │

8.6 4060 시니어 원터치 무조작 UX 규격 (P0)

8.6.1 목적 및 핵심 페르소나
* 1인 PT/재활/체형교정 스튜디오의 고단가 핵심 결제 고객인 40~60대 액티브 시니어 및 재활 회원의 조작 피로도를 0으로 만든다.
* 노안, 스마트폰 조작 미숙, 복잡한 인증/회원가입/앱스토어 다운로드 장벽을 완전 제거한다.

8.6.2 3대 무조작 원칙
1. 0초 자동 진입 (Zero Friction):
   - 카카오톡 링크 터치 시 로그인·목록 탐색 없이 "김OO 님, 오늘 5분 허리 운동" 큰 글씨와 함께 1번 운동 시범 영상 및 음성 코칭 화면으로 즉시 직행.
2. 64px 왕버튼 & 키보드 입력 박멸 (Zero Keyboard):
   - 한 화면에 단 1개의 거대 터치 타깃(64px+)만 노출.
   - 피드백은 [좋아요 / 조금 힘들어요 / 아파요] 3대 대형 이모지 칩 + 통증 부위(허리/무릎/어깨/목) 원터치 선택. 타이핑 0회.
   - 추가 의견은 마이크 버튼 원터치 음성 녹음(STT) 지원.
3. PWA 홈 화면 바로가기 & 원터치 푸시:
   - 앱스토어 설치 없이 홈 화면 추가 원클릭 지원.
   - 저녁 알림 터치 시 인트로 화면 없이 즉시 당일 1번 운동 자동 재생.
