# 1단계 — 로컬 데모 검사와 복구 기준선

2026-09-12 / 로컬 검증됨. 단계 상태는 [EXECUTION_CONTROL.md](EXECUTION_CONTROL.md)가 원본이다. DONE은 검사·보존 작업의 완료이며 전체 흐름 정상·실제 저장·파일럿 출시 승인이 아니다.

## 검사 환경과 범위

Windows, Node 20.20.0, Next.js 16.2.2, Codex 인앱 데스크톱 브라우저, `http://127.0.0.1:3100`. 기존 데모 fixture와 새 합성 회원 `로컬합성회원0912`(가상 연락처 010-0000-0000)만 사용했다. 실제 로그인·회원 데이터·외부 DB·외부 전송은 사용하지 않았다.

로컬 프로세스 환경 변수를 아래처럼 지정해 기존 `.env.local`의 외부 DB 설정 대신 닫힌 loopback을 사용했다. 설정 파일 자체는 수정하지 않았다. DB 실패 후 fallback하는 구조이므로 로딩 지연과 성공 UI는 예상 가능하나 영속성·권한의 증거가 아니다.

```powershell
$env:NEXT_PUBLIC_DEMO_MODE='true'
$env:NEXT_PUBLIC_SUPABASE_URL='http://127.0.0.1:9'
$env:NEXT_PUBLIC_SUPABASE_ANON_KEY='local-demo-no-credentials'
$env:NEXT_PUBLIC_APP_URL='http://localhost:3100'
$env:NEXT_TELEMETRY_DISABLED='1'
npm run dev -- --hostname 127.0.0.1 --port 3100
```

검사 후 서버와 임시 탭을 종료했다. 재실행할 때도 위 격리 환경을 먼저 지정한다. 기존 환경 변수 파일로 그대로 실행하여 외부 DB를 테스트하지 않는다.

## 실패 근거와 수정 경계

- 새 링크 실패: `lib/db.ts`의 브라우저 메모리 생성과 `lib/db-server.ts`의 독립 고정 fixture 조회가 분리되어 있다. 공유 저장 경계를 바꾸는 작업은 이번 기준선 검사에 포함하지 않았다.
- 다음 수업 404: `app/app/homework/new/page.tsx`가 생성 후 `resetDraft()`를 호출하고, 이동 URL을 `memberId || initialMemberId`로 구성한다. 쿼리 없이 작성하면 둘 다 비어 `/app/session`이 된다. 별도 UI 수정 후보로 남겼다.
- 후속 수정 후에는 새 숙제 생성→회원 링크→제출→해당 회원 다음 수업의 연결을 다시 검사해야 한다. 샘플 각각의 성공을 종단간 성공으로 합치지 않는다.

- `npm run verify`: exit 0, 48/48 테스트 통과, TypeScript·ESLint 통과. 기존 합성 데이터 메모리 PGlite 테스트만 실행.

- 잔존 경고: Next.js middleware 파일명 폐기 예정. DB·인증 구조 변경 금지에 따라 그대로 보존.
- `git diff --check` 통과(기존 LF→CRLF 예고만 있음). 활성 기준·이번 단계 문서의 상대 링크·단계 상태·변경 범위 검사 완료. 첫 링크 검사는 보관 핸드오프의 다른 프로젝트 `file://` 링크까지 포함해 실패했다. 보관 문서는 변경/추적하지 않고 현재 라우팅 문서 9개로 검사 범위를 바로잡았다.

## 복구 기준선

최신 폴더: `C:/Users/tmd31/.codex/visualizations/2026/09/12/01a093c4-d507-7a61-affa-0e3b0264e203/instructor-sync-stage1-baseline-2026-09-12/`

- `incomplete-attempt-1/`: 보관 문서 링크 처리 때문에 완료되지 않은 첫 검사 산출물을 분리한 폴더. 최신 복구에는 사용하지 않는다.
